5. Data Flow Architecture

Governing Principle: Deterministic scripts compute every number. LLMs only interpret and narrate. If a number is wrong, it is a bug in a script -- never an AI hallucination. This principle is non-negotiable per CEO mandate.

Architecture Diagram

COLLECT
Data Sources → Timestamped Snapshots
QuickBooks (daily 6:00 AM: balances, AR/AP; weekly: full GL; monthly: P&L close) • Atio CRM (daily 6:15 AM: pipeline, deals, stages; webhook: Won/Lost events) • Teamwork (daily 6:30 AM: time entries, budgets, milestones; weekly: utilization, compliance) • Plaid (daily 5:45 AM: bank balances -- runs first, fastest API) • Manual Inputs (on-change via PR: people.yaml, expenses.yaml, scenarios.yaml, invoice-schedule.yaml, fx-rates.yaml)
Output: snapshots/{source}/YYYY-MM-DD.yaml committed to Git. Each snapshot carries freshness metadata.

TRANSFORM
Normalize → Categorize → Validate
Currency conversion (USD → CAD via config/fx-rates.yaml) • Date normalization to ISO 8601 • Expense categorization via category-map.yaml • Schema validation (pydantic) • Cross-source reconciliation (Plaid balance vs QB balance within $500 tolerance) • Staleness check (>24h for daily sources flagged)
Runs immediately after L1. Pure function -- deterministic, no external calls. <10 seconds.

L3
STORE
GitHub Repository = Determinism Boundary
makro-finops/ repo: snapshots/ (raw + normalized), computed/ (derived metrics), reports/ (generated HTML), model/ (Excel file via Git LFS). Same commit = same output. Git history = audit trail. Branch protection on main for manual input changes (requires PR review by Rahul).
Retention: daily snapshots 90 days, monthly snapshots indefinitely, computed outputs indefinitely.

Daily: Revenue, Plan, Cash, Scorecard updated. Weekly: 13-Week Cash refreshed. Monthly: all tabs, Actuals populated.

Claude agent explains material variances in plain language. Recommendations feed back to manual inputs for next cycle. Rahul reviews and decides which adjustments to implement.

Graceful Degradation

Every data snapshot carries freshness metadata (source, timestamp, staleness_seconds). If a source is unreachable, the pipeline falls back to the last-known-good snapshot with a staleness flag on all downstream reports. Protected Floor items (daily cash email, weekly ops snapshot, monthly close, escalation triggers, payroll) ship even when degraded -- they never fail silently. Primary/fallback sources: Plaid (primary for cash) → QB (fallback) → last-known-good (last resort).

What the Architecture Does NOT Cover

  • Model-internal formula remediation (CRIT-01 through CRIT-06, HIGH-03). Those are a separate model-fix workstream in Week 1.
  • Teamwork migration change management, contractor classification audit, insurance review, process documentation authoring. Those are operational projects that consume outputs from this system.

5B. End-State Architecture: Where Does the Data Live?

Decision: The Excel model is the bootstrap, not the destination. Excel cannot be version-controlled, multi-user, API-fed, or CI-tested. The end state is a GitHub-backed data pipeline with a Google Sheets presentation layer for human review and an HTML dashboard for CEO consumption.

  • Deterministic: Python scripts in Git. Same input YAML = same output. No AI guessing. Testable with pytest. CI catches regressions.

  • Resilient: If Google Sheets is down, pipeline still runs, alerts still fire, dashboard still updates from YAML. If one source is unreachable, staleness flag propagates — reports ship with [STALE] marker, never silently.
  • Delegatable: Mike's concern: "How do I transfer this to Rahul?" Answer: the knowledge lives in code + config, not in anyone's head. thresholds.yaml is self-documenting. Scripts have docstrings. New hire reads the repo README and understands the system in an hour.
  • Evolvable: Adding a new metric = add to thresholds.yaml + add formula to metric_engine.py + add column to Sheets. No architectural change.

Cash Flow Forecasting

SourceKey FindingRelevance to Makro
Wall Street Prep, Dwight Funding, McCracken Alliance
13-Week Cash Flow Model		 Fixed column layout (Week 1-13). Weeks 1-4: bottom-up from known data (target +/-5% accuracy). Weeks 5-13: top-down from assumptions (+/-10-15%). Weekly Monday refresh ~60 minutes. Pipeline deals only enter weeks 9-13 with probability AND cash-conversion-timing haircut. Makro's Monday refresh pulls: actual bank balance, QB AR aging for weeks 1-4, Teamwork milestones for invoice timing, Atio pipeline for weeks 9-13 only. Payroll is ~65% of outflows -- mapping to actual pay dates is why weekly granularity matters.
FINOYA, Centime, Tesorio
AR Waterfall Mechanics		 "Invoiced" does not equal "collected." Full chain: milestone completion → invoice generation (1-7 days) → client processing → payment → bank clearing. Typical PS firm: 41-48 actual days vs contractual 30-day terms. Collection probability: 73% after 90 days, <50% after 6 months. Build client-segment lookup with observed collection days. AR Waterfall tab pulls existing AR from QB by aging bucket + future invoices from Teamwork milestone dates + segment-specific lag = cash week. This is the technical core that makes the forecast accurate.
Forecastio, Prospeo
Pipeline-to-Cash Conversion		 Pipeline deals need TWO haircuts before entering cash forecast: close-probability AND cash-conversion-timing. For a 20-person agency: close → SOW → kickoff → first deliverable → invoice → collection = 8-13 weeks. Pipeline deals populate ONLY weeks 9-13. Retainer deals (TA Appliance, Clarius) produce cash faster (deposit at signing, monthly billing). Milestone-based projects (Rapido, MA Matting) have longest cash conversion. Segment deals by type and apply different timing assumptions.
